# Raw app-path Ollama stream diagnosis

Dataset: first 20 rows of `eval/dev.jsonl` (DEV, not held-out).

The fine-tuned thesis-student GGUF was unavailable. Both student columns use matched public Q4_K_M base weights to isolate intended versus stale template behavior; neither is the real student.

Each request was built by the app's `_guarded_chat_body(app_messages(...))` path with `stream:true`, `think:false`, temperature 0.2, context 4096, prediction cap 512, repeat penalty 1.1, the app keep-alive setting, and no seed. One synthetic excerpt containing the DEV gold answer was supplied to keep this a generation/stream sanity check rather than a retrieval-quality check.

App options: `{"num_ctx": 4096, "num_predict": 512, "repeat_penalty": 1.1, "temperature": 0.2}`

The complete system prompt is saved beside this report. The app sends the same +RAG+CoT thesis prompt and formatting overlay to every model role. The intended ChatML template renders `.System` and `.Messages`; a stale plain `{{ .Prompt }}` template does not explicitly render either field, so the deployed student's Modelfile still determines whether the model sees it.

The stock Ollama model also displays `{{ .Prompt }}`, but pairs it with the Qwen3.5 renderer and parser; it is not equivalent to a stale export that has neither.

This statement applies only to the exact model IDs recorded below. A proxy capture does not establish what an unavailable fine-tuned student emits.

## Interpretation

The stock Q8_0 model, matched Q4_K_M base, intended-template proxy, and stale-template proxy all reach the app as multi-sentence Markdown and stop naturally. That rules out the common app request options, raw stream transport, and Q4 quantization as causes of a one-sentence stream in these available reproductions.

Changing only the matched base's template from intended ChatML with `<|im_end|>` to the stale plain template without a renderer/parser also did not reproduce the symptom. Therefore the stale template remains a deployment defect, but it is not sufficient by itself to explain the reported behavior on base weights.

The untested variables are the real fine-tuned student weights and its actual ThinkPad Modelfile. The frozen KD target shape from those weights is already known to put numbered `Steps:` before `Answer:`, which the UI parser hides without this PR's compatibility fix. Capturing the real tag is still required to determine whether that model also emits a genuinely short raw stream.

## Capture the actual ThinkPad tags

From the repository root on the ThinkPad:

```bash
python docs/diagnostics/capture_ollama_streams.py --prefix student-output-actual
```

The defaults are `qwen3.5:2b`, `thesis-base-q4km`, and `thesis-student`; the command fails instead of substituting another model when a tag is unavailable.
